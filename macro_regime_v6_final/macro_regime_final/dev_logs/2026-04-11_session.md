## Changes Already in Place (pre-session)

### 1. Model-derived continuous exposure
Replaced hardcoded `EXPOSURE_MAP` (Expansion=1.20, Transition=1.00, Contraction=0.50) with a fully automatic system:

```
exposure = Σ P(state_i) × health[state_i]
```

- `health[state]` is derived from the HMM's own emission means using the same risk-score formula used to label states
- `health[Expansion] = 1.0`, `health[Contraction] = 0.0`, `health[Transition]` = whatever the model produces
- Clipped to `[regime_posterior_floor, 1.0]` where floor = 0.10
- Only one human parameter remaining: the floor

**Why:** The old multipliers were effectively tuned by backtest results. Any in-sample tuning that leaks into OOS is overfitting. Now weights come purely from the model's own structure.

## Bugs Fixed This Session

### Bug 1 — `classify_oos` missing `health_weights`
`classify_oos()` in `regime_engine.py` referenced `health_weights` at line 482 but never computed it.  
**Fix:** Added `health_weights = _compute_state_health_weights(model, state_labels, feature_cols)` after `state_labels` on line 451.  
**Impact:** Would have crashed on the first OOS rebalance date at runtime.

### Bug 2 — Kill switch multiply vs override (semantic bug)
`apply_kill_switch_to_returns` was doing:
```
PortRetKS = PortRet × contraction_exp
           = (gross_ret × regime_exp) × contraction_exp   ← wrong
```
But `PortRet` already has `regime_exp` baked in. The docstring says "override", but the code was compounding exposures.

**Fix:** Changed to a true override:
```
scale = (contraction_exp / regime_exp).clip(upper=1.0)
PortRetKS = PortRet × scale
```
Kill switch now replaces regime exposure rather than multiplying on top of it. Scale is capped at 1.0 — kill switch never increases exposure.

Added `regime_exp_col: str = "RegimeExp"` parameter to `apply_kill_switch_to_returns`. Falls back to legacy multiply behavior if the column is absent.

### Bug 3 — Kill switch using wrong parameter
After removing `regime_exposure_contraction`, the kill switch was reading `regime_posterior_floor = 0.10` as its override exposure. These are different concepts:
- `regime_posterior_floor` = minimum exposure the HMM can produce under uncertainty
- Kill switch exposure = the level to force during a HY OAS spike emergency

**Fix:** Added dedicated `kill_switch_contraction_exp: float = 0.20` to config with clear docstring. Updated all three call sites in `backtest.py` and `get_kill_switch_status` in `kill_switch.py`.

## Crash Protection Design Notes

Three layers of protection:

1. **Quarterly regime** — when `P(Contraction) → 1.0`, health[Contraction]=0.0, exposure → floor (0.10). More defensive than old 0.30.
2. **Continuous blending** — exposure starts falling before the regime is fully labeled Contraction. Reduces exposure earlier than the old discrete snap.
3. **Kill switch** — intra-quarter HY OAS spike protection, overrides to 0.20. Only protection between quarterly rebalances.

Key thing to verify in results: kill switch fires during GFC (late 2008) and COVID (March 2020). If it doesn't, the threshold or HY OAS data has an issue.
